# 05: 设备列表的完整状态与连接

Status: done

**Parent:** [数据同步：把本机配置推送到远端设备](../../remote/data-sync.md)

**What to build:** 数据同步页的设备列表覆盖本机已知的全部可同步设备。未连接的设备显示灰点、「未连接」和「连接」按钮。需要安装、升级、确认身份或输入凭据的设备也显示为「未连接 + 连接」。点击「连接」打开连接向导；连接期间设备行显示「连接中…」；连接成功后回到数据同步页，按钮变为「同步」；失败则回到「连接」。设备在线但上次同步失败或部分失败时，显示红点、「上次同步失败」和 outline 样式的「重试」，点击打开同步弹窗。没有任何设备时显示空状态和「连接远端设备」按钮，打开已有的连接向导。未安装的设备、所有连接配置都已退役的设备不出现。

**Blocked by:** [04: Tracer：数据同步页与技能推送](04-data-sync-page-skill-push.md)

## Acceptance criteria

- [x] 设备行的状态点、文案、按钮严格按 spec 的设备状态表实现：在线成功、在线从未同步、在线同步失败、连接中、离线 / 连接失败 / 待处理。
- [x] 待处理（需安装 / 需升级 / 待确认身份 / 缺凭据）显示为灰点、「未连接」和「连接」。安装、升级、身份确认和凭据输入由连接向导处理，数据同步页不另做处理。
- [x] 「连接」打开已有的连接向导，执行设备级连接，不打开项目、不创建项目，也不新增连接链路。
- [x] 连接向导的 `returnTarget` 新增 `data-sync`。从数据同步页打开时传入它；连接成功后回到数据同步页，不跳到「远程设备」页。
- [x] 连接状态只取自 Source Server 管理快照，不在页面内另存连接状态；取消或迟到的连接结果不改变页面。
- [x] 「上次同步失败」只取自 04 的设备同步状态，`partial` 与 `failed` 都显示为失败。
- [x] 空状态的「连接远端设备」以设备管理模式打开连接向导，`returnTarget` 同样为 `data-sync`；成功后回到数据同步页，新设备出现在列表中。
- [x] 设备过滤：只显示 `installState` 为已安装、且至少有一条未退役（`lifecycleState` 不是 `retired`）Connection Profile 的设备；dev-only 的 Server 直连不显示。
- [x] 传输方式和目标地址取自 Connection Profile；一台设备有多条 Profile 时，沿用 `getRemoteDevicePresentationInput` 的选择规则。
- [x] 中英文文案齐全；深浅主题下各状态点都可辨识。
- [x] 先补测试再改代码。

## Verification

- Seam ②：注入不同的管理快照和设备同步状态，断言 5 种设备行、待处理设备的显示、按钮可用性、空状态和过滤规则（未安装、Profile 全部退役、dev-only 直连）；「连接」和空状态按钮以 `returnTarget: 'data-sync'` 打开连接向导。
- Seam ③（本机 Docker 远端 runner）：用 runner 提供的离线 / 恢复操作让设备离线（容器重启后端口保持不变）；恢复后在数据同步页点「连接」，在连接向导中完成连接，断言回到数据同步页、设备行变为「同步」，最后可以打开弹窗。
