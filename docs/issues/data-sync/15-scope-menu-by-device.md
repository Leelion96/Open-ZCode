# 15: Scope 菜单按设备分组

Status: done

> 菜单结构已由 [19: Scope 菜单的项目收进各设备的子菜单](19-scope-menu-project-submenu.md) 修订：第一层不再平铺项目。下方设计稿保留为本票当时的结构。

**Parent:** [数据同步：把本机配置推送到远端设备](../../remote/data-sync.md)

**What to build:** 所有使用共享 Scope 菜单的配置设置页（插件、MCP、技能、子智能体、命令、钩子）改为按设备分组：

- 「本机」下列出「用户」和本机项目；每台在线远端设备以设备名为标题，下面列出「用户」和该设备的项目。
- 触发器显示「设备 · 用户」或「设备 · 项目」，本机也带设备名（例如「本机 · 用户」），用户始终知道自己在改哪台设备。
- 不打开远程项目，也能直接编辑远端设备的用户级配置。
- 打开设置时，默认选中当前 workspace 所在设备的「用户」。

这样也消除了现在各页 User scope 归属不一致的问题：子智能体固定写本机，命令、钩子、技能、MCP 跟随当前 workspace。

记忆查看页不在本票范围内，本期不变。

**Blocked by:** [14: 旧同步入口统一与旧弹窗删除](14-route-legacy-sync-entries.md)

## Acceptance criteria

- [x] 菜单结构遵循设计稿：设备标题、平铺的「用户」和项目、设备之间的分隔线；不再显示单独的「工作区」小标题；离线设备不列出。
- [x] 数据来自配置目录目录表，按 hostId 分组；设备名取自本机 Source 设备记录。不新增目录事实源。
- [x] 远端设备的「用户」通过该设备的 source-settings attachment 读写，不要求打开项目；远端项目沿用现有的配置专用服务解析。
- [x] 默认选中规则：本地 tab 为「本机 · 用户」，远程 tab 为「该设备 · 用户」。各页统一执行这条规则，取消子智能体页「User 固定写本机」的特殊处理。
- [x] 触发器显示「设备 · 用户」或「设备 · 项目」，设备名在前；本机显示「本机 · 用户」或「本机 · 项目」。分隔点使用 `DESIGN.md` 中的次级文字色。
- [x] 记忆查看页不改：仍只读本机的记忆目录，不按设备分组。
- [x] 选中的设备离线后，该页的读取和写入一律失败并提示（fail-closed），不回退到本机，也不显示可写的旧快照；迟到的结果只属于原目标。
