# 19: Scope 菜单的项目收进各设备的子菜单

Status: done

**Parent:** [数据同步：把本机配置推送到远端设备](../../remote/data-sync.md)

**Revises:** [15: Scope 菜单按设备分组](15-scope-menu-by-device.md) 的菜单结构

**Problem:** 15 号票把每台设备的「用户」和全部项目平铺在一个列表里，本机分组排在最前。本机项目一多（实测 40 个以上），远端设备的「用户」就排在几十项之后，切换设备要滚很长。项目名只显示目录末段，同名项目和截断后相同的长名无法区分。

**What to build:** 第一层只按设备列出「用户」和一个「项目」入口；项目放进该设备的子菜单。

```text
[本机 · 用户 ▾]
 ┌──────────────────────┐
 │ 本机                  │
 │  ● 用户            ✓ │
 │  ▸ 项目         42 › │──┐  子菜单（独立浮层，rounded-lg）
 │ ──────────────────── │  │ ┌──────────────────────────┐
 │ linux-amd64-dev       │  └▶│ 🔍 搜索项目               │ ← 项目超过 8 个才显示
 │  ○ 用户               │    │ ○ z-code       workspace │ ← 同名项目在右侧显示上级目录
 │  ▸ 项目          5 › │    │ ○ z-code       worktrees │
 └──────────────────────┘    │ ○ ai-switcher            │
                             └──────────────────────────┘
选中某个项目时，该设备的「项目」行显示「项目名 ✓」，触发器显示「设备 · 项目名」。
```

- 第一层的长度只和设备数有关。切到某台设备的「用户」：打开菜单，点一次。
- 选项目：打开菜单 → 悬停或点击该设备的「项目」→ 点击项目。
- 页面级菜单和表单内菜单使用同一结构；表单内菜单仍只列出所在设备。
- 原型（一次性，未入库）对比过两种方案：拆成「设备」「范围」两个下拉（多一个控件，跨设备选项目要操作两次），以及本方案。用户选定本方案（2026-10-19）。

## Acceptance criteria

- [x] 第一层每台设备一个标题，下面是「用户」（有时）和「项目」入口（该设备有项目时）；不再平铺项目。离线设备仍不列出。
- [x] 「项目」入口右侧显示项目数；选中的是该设备的某个项目时，改为显示项目名和对勾。
- [x] 子菜单列出该设备的全部项目，可滚动；项目超过 8 个时顶部显示搜索框，按项目名和路径过滤（不区分大小写），没有匹配时显示空状态。
- [x] 同一设备内同名的项目，右侧显示上级目录名；每个项目悬停显示完整路径。
- [x] 触发器、默认选中、fail-closed、离线、回退等 15 号票的规则不变。
- [x] 桌面、Web 与手机使用同一结构，不按断点换组件（`DESIGN.md`「Responsive Behavior」）；子菜单的位置由下拉组件的碰撞避让处理。Web 与手机的远端设备没有「用户」，只显示「项目」入口。
- [x] 子菜单是独立浮层：外壳 `rounded-lg`，选项 `rounded-md`（`DESIGN.md`「Menus and selection overlays」）。
- [x] 中英文文案齐全；深浅主题可读。
- [x] 先补测试再改代码。

## Verification

- 单测（`packages/ui/test/pluginScopeMenuDevices.test.ts`）：第一层结构、项目数与选中项显示、子菜单项目列表、搜索阈值与过滤、空状态、同名项目的上级目录、表单内菜单。
- E2E：所有按 Scope 选项目的用例改为先打开该设备的「项目」子菜单（共用 helper）；DSYNC-15-01 的菜单结构断言按本票修订。

## Comments

- 2026-10-19 实施：窄窗口下子菜单左右两侧都放不下 `w-64`，最小宽度改为不超过可用宽度（沿用 `ModelConfigSelect` 的写法）。480px（桌面最小宽度）时子菜单在右侧、宽约 140px；低于桌面最小宽度（只可能是 Web）时子菜单变得很窄，项目名靠悬停的完整路径辨认。
