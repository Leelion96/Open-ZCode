# 桌面应用品牌文字

## 目标与规则

桌面应用的本地自有文字不再向用户展示上游 ZCode 品牌，范围包含内嵌 Agent 的身份与说明。Logo、图标及图形回退保留现状；DMG 安装背景仅去除品牌文字，保留其他元素及普通版/Retina 版原尺寸；独立 CLI/Web 的发布、Computer Use Helper 与远端运行组件不扩展。

逐句按原语义处理：

1. 省去品牌主体后含义基本不变、句子仍通顺的，直接省去主体，使用固定文案。
2. 需要明确应用、账号或运行环境范围的，保留原句并使用配置名称。
3. 原文指 Agent、subagent 或主 Agent 身份的，保留该实体；不把应用、窗口或登录改称 Agent，不为去品牌额外引入 Agent 主体。

配置名称来自 `packages/shared/src/product.ts`，默认使用 `name`，没有品牌开关。语言字典沿用 `{productName}` 和既有 `IntlProvider`，其他消费处使用原有模板或格式化入口。保留消息 ID、业务占位符、中英文语义、原句结构与源码风格，不新增覆盖表、新旧展示选择或全局文字转换层。

## 接入范围

| 大类 | 当前消费入口及规则 |
| --- | --- |
| 应用内文字 | 欢迎、引导、未登录名称回退、顶栏及侧栏文字、工作区窗口标题、设置说明、资源管理器与反馈中的自有展示名。alt/aria-label 使用名称，实际用户昵称和头像不改。 |
| 原生及系统文字 | HTML 初始标题、About、菜单、托盘、Endpoint 窗口、外部链接确认、强更提示、系统打开文件夹标签与安装器输出。只改自有展示文字，不改路由、信任、更新或安装行为。 |
| 内嵌 Agent | 主身份入口、进程展示名、MCP 默认客户端名和 OAuth metadata 使用配置名称；用户显式 clientName 优先。通用错误、内部提示词和能力介绍直接使用技术对象或省略主体。 |
| 本地说明与兜底 | 本地市场介绍、Guide 名称/说明/示例、预置 MCP 额度说明和运行组件下载说明使用通用文案。保留原来的 3.x 试用条件、任务执行范围、权益含义和外部来源。 |
| 新生成的资料 | 默认项目目录按 `<名称>Project` 派生；忽略文件说明、新 CA subject、Checkpoint 名称/主题、诊断包及 README 使用配置名称。提示与真实生成值一致，不重命名或重建已有资料。 |
| 错误与恢复 | 自有错误在生成处精简主体或使用名称，既有回收判断、详情筛选和 transcript 取消恢复同步识别。历史 ZCode、Agent 及配置名称标记仅用于兼容读取，不能重新展示成旧品牌或误判第三方错误。 |

About 保留原中英文版权句式及动态年份，仅替换应用名，不改写成许可指引。LICENSE、NOTICE 和第三方版权保留来源署名。打包产物的公司、Windows 已安装应用 Publisher、版权及 Linux maintainer 名称统一使用配置 name；在 electron-builder 消费处覆盖，不修改源码包名或源文件中的上游署名。版权年份保持动态，签名身份仍由实际证书配置决定。 DMG/EXE 的发行元数据不包含 homepage 或 author.email；Linux 保留原有网址、邮箱与维护者处理，保证其打包要求不受影响。

Helper 相关系统权限说明使用实际 displayName，使其与系统列表一致；不改名或启用 Helper。应用身份开关关闭时的原生应用名称边界不扩展处理。

## 内容归属边界

外部 API 消息、公告、release notes、listing、作者、模型输出、用户消息、文件内容及第三方错误按来源显示。纯服务端提供的内容不改，本地兜底按上述规则处理；不能用产品名猜测服务域名、商品归属或第三方名称。

技能内容不受品牌配置控制。用户、第三方、缓存及下载的技能按上游方式读取，不在列表、详情、Agent 技能描述或 Skill 工具正文中新增品牌替换与展示覆盖。保留上游既有本地化、预算裁剪、when_to_use 合并和技能目录变量展开。

仓库内置技能仅直接精简 `SKILL.md` 的 description 中不必要的品牌：`apps/zcode-cli/packages/browser-use-plugin/skills/control-browser/SKILL.md` 去掉 `inside ZCode`。正文、权限和工具指令保持原样，其他来源不改。

自带 Browser Use 文档在仓库源文案中去品牌；读取、下载或缓存文档时返回原文，不做品牌替换或目录归属猜测。Browser API、文档选择和能力裁剪保持原语义。

内部包/类/函数名、协议和 IPC、env/header key、错误码、事件、provider/工具/市场/技能 ID、CSS 类、历史格式及兼容标记不为品牌改名。实际私有路径由三个隔离开关控制，品牌文字不重新定义路径。

## 构建与运行一致性

桌面 Agent 构建读取一次产品配置，并传给主 Agent 和 Node REPL；Node REPL 的进程展示标题及桥接错误使用同一名称。Browser SDK 不注入产品配置。

桌面 Agent 的 Turbo 任务不使用缓存，确保每次重新读取配置并构建 Node REPL；普通依赖继续使用原有缓存。Browser SDK 作为普通构建依赖，声明 `dist/**` 和 `scripts/browser-client.mjs` 产物，避免缓存恢复遗漏脚本。

进程命名与崩溃分类共用 `PRODUCT_PROCESS_PREFIX`，沿用 Electron serviceName 的识别优先级。Host/Agent 异常崩溃保留 `perf_crash`，正常/killed 退出和普通 Chromium Utility/GPU 保留 `perf_process_exit`；不改变遥测字段、地址或策略。

## 验收

- 核对本地自有显示文字，中英文及业务占位符一致；通用文字不再为品牌依赖配置。
- 检查 About、菜单、系统入口、窗口标题与内嵌 Agent 的名称，生成资料名称及路径提示与实际值一致。打包公司/Publisher/版权名称与配置一致；DMG 背景无品牌文字，普通版为 540×380，Retina 版为 1080×760。
- 技能及 Browser 文档保持源内容；外部 API、用户及第三方内容不被转换，上游既有本地化与目录变量展开仍可用。
- 新旧取消标记均正确恢复，泛化错误优先展示真实原因；非回收错误不误判，历史忽略分区的用户自定义段保留。
- 配置名称变化后，主 Agent 与 Node REPL 使用同一配置，Browser SDK 无品牌转换；Host/Agent 崩溃分类与既有正常退出语义一致。
- 使用既有配置/隔离测试、类型检查、Lint、架构检查与桌面构建，不新增品牌专项测试文件或命令。真实应用界面由用户验证。
