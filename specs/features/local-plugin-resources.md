# 客户端基础内置插件与服务端市场

## 产品规则

- 客户端仅内置 Browser Use 与 Node Repl Host，继续从原有源码包构建；不改动这两个插件的技能、文档或运行实现。
- 其余 21 个可用插件由独立 Open-ZCode-Server 仓库管理、构建和分发，通过现有市场发现与安装流程使用。客户端不再保存提取原件、ZIP 或临时适配副本。
- 默认市场地址由现有 ZCODE_BASE_URL 地址解析器和固定路径 /api/v1/plugins/marketplace.json 组合；兼容既有 ZCODE_ENDPOINT_ORIGIN 别名与构建注入的公开配置，不在业务代码固定部署域名或端口。目录继续使用稳定技术 ID zcode-plugins-official。
- Server 目录持有插件分类、展示信息、作者、版本和下载哈希；客户端不能继续把远端插件登记为本地内置，或在尚未安装时自动视为启用。
- 用户已排除依赖原官方账号/套餐的插件与旧版会话恢复，保留第三方 CLI 插件。发行范围由 Server 目录控制，客户端复用通用发现和安装流程，不再维护具名黑名单。

## 所有者与边界

- 按真实使用方界定范围：桌面 Agent 与独立 CLI 共用的配置允许同步更新；仅独立 CLI 使用的入口、TUI、命令解析、SEA 打包算法和 README 不在本次修改范围。目录名不能代替读取关系判断。
- Server 是新增 21 个插件发行内容和市场目录的唯一所有者；客户端构建不读取相邻 Server 仓库。
- 桌面 Agent 与独立 CLI 共用的内置 definition 持有两个基础插件的运行时归属和默认启用规则，市场默认地址也由共用配置提供。共享设置中的默认启用集合必须与其一致，不建立两套配置。
- 既有 SEA 构建清单持有两个源码插件的资产位置、版本及必需文件；Desktop 开发和打包复用该清单与原资产白名单。仅导出原白名单供桌面读取，CLI 专用资源采集逻辑保持原样。现有 bundled-skills 仍随包携带，不改造成市场插件。
- Agent storage 继续持有市场缓存、安装记录和启停状态。调用现有 refresh / install 路径，不增加安装或持久化通道。
- 市场来源在读取时解析当前配置，不在模块导入时冻结地址。启动配置修改后通过对应 Agent 的新配置生效，不新增应用内地址设置或热切换协议。
- 默认渠道由应用配置管理。Agent 同步新来源时保留 addedAt，清除旧来源的刷新状态及远端目录分片，重新合并本地内置分片；个人来源、installed_plugins.json、插件缓存和数据目录不变。
- 地址切换后，内置分片的存在不能阻止远端目录重新获取。远端获取失败保持本地资源可见，不回退到旧来源的目录。
- 每次远端刷新捕获来源上下文；获取和持久化过程中来源已变化时，旧结果不得重新发布或把失败状态写到新来源。
- 基础内置插件恢复原有 MCP manifest 处理和资产白名单；Server 下发插件继续由既有 ZIP 安装器与运行时加载。回退临时内置适配、客户端黑名单及对应缓存忽略规则，不改动其他会话的品牌、DMG、产品身份和 API 设计资料。
- 本次不处理老用户迁移，不清理正常用户目录、会话或插件数据。清理前留存源码与资源备份，备份不参与构建。
