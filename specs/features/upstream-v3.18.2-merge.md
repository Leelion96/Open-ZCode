# v3.18.2 合并边界

将上游 `fec975905a2abd4c07e35c40d51fa097a2258ec9` 合入 Open-ZCode 的 `18bdfbed`，形成独立的双亲提交。共同基线为 `c5904686`。产品策略沿用 [v3.18.1 合并规格](upstream-v3.18.1-merge.md)。

## 产品规则

- 切换数据目录时，凭据密钥登记与目录复制使用同一产品的用户资料目录。用户资料隔离开关决定目录名，项目隔离开关只影响项目。Desktop Main 独占系统密钥，Host 只接收结果；目标存在冲突密钥时，中止切换并保留原设置。
- Linux Desktop 支持在未绑定来源且系统库不可用时生成用户私有文件密钥。已有系统库密文或来源标记的目录继续走系统库。独立 CLI 和服务器沿用自己的存储策略。
- 接入上游国内未关联账号的 Start Plan 家族解析。默认 fork 的跳过登录、自定义 Provider 和商业入口可见性继续由既有产品策略决定。
- Windows 自建更新源沿用现有信任规则，接入受限 PowerShell 环境下的签名查询与路径处理。
- 同步上游两项桌面候选用例和 CLI、工程回归，保留候选状态。源码版本更新到 v3.18.2。

```text
设置页 → Host 复制产品 v2 目录 → Main 按目标凭据文件登记系统密钥
                             → 成功后 Host 保存新路径 → 重启读取目标凭据
                             → 登记失败 → 保留原启动路径
```

## 验收

核对 46 个上游路径与 11 个 fork 重叠路径。验证目标资料目录、CLI 凭据读写与回退、Windows 签名查询、自建更新源、默认模型设置入口。执行根类型检查、Lint、架构门禁、桌面 E2E 类型检查，并复核本次变动的 React Hooks。系统凭据故障与目录迁移使用测试副本。桌面 E2E 的官方插件预热缓存与迁移用例按构建配置定位用户根，使凭据用例在默认隔离配置下可以进入桌面。

## 合并结果

解决中英文 README 和更新源回归脚本三处内容冲突。README 标注新的上游版本，更新测试同时覆盖 fork 的可信源和上游的签名结果文件协议。与第一父提交比对，`config/`、`packages/provider/`、`packages/provider-node/` 内容相同。模型设置继续使用 fork 的 Default Plan 占位和自定义供应商导航。

- macOS 原生数据根切换 E2E 通过 1/1。在测试专用目录和按路径生成的钥匙串条目上，验证复制、登记、冷重启、解密和再次写入。产物为 `packages/desktop/.e2e-artifacts/desktop-e2e-20261123-102032-811/summary.md`。
- 凭据 CLI 测试 42/42 通过。使用真实目录复制和注入的系统库替身，自定义产品名下四种用户／项目隔离组合均通过，目标目录可冷读写，另一用户目录未被创建。合成国内未关联账号仅取得 BigModel 的 Start 身份，自定义模型导航渲染检查通过。
- 工程测试 3 文件、35 项通过、5 项 Windows 原生用例按平台跳过。Electron 可信更新源测试覆盖默认、AppImage 和 NSIS 三组，各 11 项。
- Node 24.14.0、pnpm 10.33.2。根类型检查、桌面 E2E 类型检查、schema 兼容与架构门禁通过。根 Lint 为 0 错误、537 条警告，两个改动 React 文件的 7 条 Hooks 诊断与合并前一致。
- 首次桌面测试发现插件预热写入产品用户目录后仍按官方目录检查，已统一夹具路径。首次类型检查遇到缺失的桌面导航声明，重建对应 TypeScript 产物后通过。复用构建时 Host 曾取到类型检查生成的未打包文件，最终按顺序重新构建桌面再跑原生 E2E 通过。
- Windows 受限 PowerShell、Linux Secret Service 及真实官方账号流程未经实机验证。官方商业入口关闭的 fork 仅验证其底层账号材料与默认模型导航。
